# پروژهٔ نهایی فصل ۷۳ — بستهٔ آموزشیِ مدل ساختگی

این آزمایشگاه یک مدل لجستیکِ بسیار کوچک را از ابتدا روی ۸ ردیفِ دستی و ساختگی آموزش می‌دهد، روی splitهای ازپیش‌ثبت‌شده سنجه‌های توصیفی می‌سازد و checkpoint، گزارش محیط و manifest هش‌ها را در یک بسته کنار هم می‌گذارد. هدف، تمرین تحویل‌دادنی‌های یک پروژهٔ مستقل است؛ خروجی، مدل واقعی یا شاهد کیفیت کاربردی نیست.

## منشأ و مرز داده

`synthetic_fixture.json` دادهٔ واقعی یا خروجی مدل بیرونی نیست. برچسب آن با قاعدهٔ آشکار `x1 + x2 > 0` ساخته شده و هیچ شخص یا رویداد واقعی را نمایش نمی‌دهد. `fixture_manifest.json` digest فایل را ثابت می‌کند؛ `data_card.md` منشأ، split، استفادهٔ مجاز و محدودیت را توضیح می‌دهد. هش فقط تغییر bytes را نشان می‌دهد، نه صحت علمی.

## اجرا

از همین پوشه اجرا کنید. فقط کتابخانهٔ استاندارد Python لازم است؛ شبکه و GPU استفاده نمی‌شود.

```bash
python3 -m unittest -v
python3 capstone.py --fixture synthetic_fixture.json --output-dir /tmp/ch73-capstone-run
cmp results.json /tmp/ch73-capstone-run/results.json
cmp checkpoint.json /tmp/ch73-capstone-run/checkpoint.json
python3 capstone.py --output-dir /tmp/ch73-capstone-run --verify-only
```

`checkpoint.json` و `results.json` خروجی‌های محاسباتی‌اند و با ورودی و پیکربندی یکسان باید بایت‌به‌بایت برابر باشند. `environment.json` نسخهٔ واقعی Python و پلتفرم را ثبت می‌کند، پس در runtime متفاوت انتظار می‌رود فرق کند؛ `release_manifest.json` هم hash محیط همان اجرا را نگه می‌دارد. فرمان `--verify-only` manifest تازه‌ساخته‌شده را در همان پوشه بررسی می‌کند. مقایسهٔ environment و manifest با snapshot فقط وقتی معنا دارد که runtime ثبت‌شده نیز یکسان باشد.

## اجزای تحویل

- `run_card.json`: هدف، splitهای مجاز، پیکربندی ثابت و حدود تفسیر را پیش از آموزش ثبت می‌کند.
- `synthetic_fixture.json` و `fixture_manifest.json`: دادهٔ ساختگی و digest آن.
- `capstone.py` و `test_capstone.py`: ابزار CLI و آزمون‌های ساختاری، آموزشی و بسته‌بندی.
- `checkpoint.json`: وزن‌های مدلِ آموزش‌دیده روی train، به‌همراه شناسه و digestهای منشأ.
- `results.json`: سنجه‌ها و پیش‌بینی‌های همان fixture؛ نه برآورد عملکرد واقعی.
- `environment.json`: نسخهٔ Python، وابستگی‌ها و مرز اجرای ثبت‌شده.
- `data_card.md` و `model_card.md`: مستندات دو artifact با دامنهٔ متفاوت.
- `release_decision.json`: اجازهٔ انتشارِ بستهٔ آموزشی را از اجازهٔ deployment جدا می‌کند؛ deployment مسدود است.
- `release_manifest.json`: SHA-256 فایل‌های منتخبِ منبع و خروجی را ثبت می‌کند؛ خود manifest را به‌دلیل نبود امکان hash خودارجاعی پوشش نمی‌دهد.

## تفسیر نتیجه و تصمیم انتشار

دقت ۴/۴ test در کنار baseline اکثریتِ ۲/۴ فقط نشان می‌دهد کد روی چهار نقطهٔ ساختگی، قاعدهٔ خطیِ آشکار را اجرا کرده است. داده و برچسب با یک قاعده طراحی شده‌اند؛ تعداد ردیف‌ها ناچیز است و دادهٔ بیرونی، افراد، گروه‌های هدف یا کاربرد واقعی در کار نیست. نتیجه نه آزمون آماری است، نه بازتولید پژوهش بیرونی، نه تأیید انصاف/ایمنی، و نه برآورد تعمیم.

بسته برای مطالعه و اجرای تعلیمی در مخزن منتشر می‌شود؛ مدل برای کاربر یا تصمیم دربارهٔ انسان‌ها تأیید نشده است. مجوز downstream مستقل بررسی نشده، بنابراین عمومی‌بودن مخزن را مجوز بازاستفاده تلقی نکنید. برای کاربرد واقعی باید مسئله، داده و حقوق، ارزیابی متناسب با دامنه، آسیب‌های ممکن، پایش و مسئولیت نگه‌داری از ابتدا بازبینی شوند.
