# پروژهٔ فصل ۴۰: آماده‌سازی یک پیکرهٔ متنی کوچک

این پروژه قبل از مدل، یک خط لولهٔ دادهٔ قابل‌بررسی می‌سازد: manifest با منشأ و مجوز، اعتبارسنجی، پاک‌سازی محافظه‌کارانه، حذف تکرار دقیق، تقسیم گروهی train/validation/test و واژگان کلمه‌ای که **فقط روی train** آموخته می‌شود. اجرای پیش‌فرض هیچ سایت یا دیتاستی را دانلود نمی‌کند؛ ۱۶ جملهٔ کوتاه فارسی در `sample_corpus.jsonl` برای همین مثال نوشته شده‌اند.

## اجرا

- Python 3.11 یا جدیدتر؛ فقط کتابخانهٔ استاندارد Python؛ CPU کافی است.
- از این پوشه اجرا کنید:

```bash
python -m unittest discover -v
python small_corpus.py
```

برای خروجی در مسیر دیگر:

```bash
python small_corpus.py --manifest sample_corpus.jsonl --output /tmp/ch40-corpus --seed 40
```

اجرای نمونه با seed برابر ۴۰، ۱۶ رکورد را نگه می‌دارد: ۱۲ train، دو validation و دو test؛ به‌ترتیب ۶، ۱ و ۱ گروه مستقل. چون پیکره کوچک است، نسبت رکوردها دقیقاً ۸۰/۱۰/۱۰ نیست. واژگان آموزشی ۱۰۲ شناسه دارد (چهار نشانهٔ ویژه و ۹۸ نشانهٔ مشاهده‌شده در train)؛ این اندازه صرفاً مشخصات همین نمونه است.

## فایل‌های خروجی

- `train.jsonl`, `validation.jsonl`, `test.jsonl` — رکوردهای پاک‌سازی‌شده همراه با منشأ، گروه و hash متن نرمال‌شده.
- `vocab.json` — ترتیب ثابت نشانه‌ها، قرارداد نرمال‌سازی و واژگان؛ `<pad>`, `<unk>`, `<bos>`, `<eos>` چهار شناسهٔ نخست‌اند.
- `duplicates.json` — تکرارهای دقیق و فرادادهٔ منشأ، گروه، مجوز و attribution هر دو رکورد (بدون ذخیرهٔ متن تکراری).
- `summary.json` و `data_card.md` — شمارش‌ها، گروه‌های هر split، seed، مجوزها و محدودیت‌ها.

`build/` خروجی محلی است و با `.gitignore` وارد مخزن نمی‌شود. شناسه‌های split در گزارش ذخیره می‌شوند تا نتیجه قابل‌بازبینی باشد.

## قرارداد داده و محدودیت‌ها

هر ردیف JSONL در این مثال `id`, `group_id`, `text`, `source`, `license`, `attribution`, `language`, `acquired_at` و `rights_note` دارد. allowlist برنامه (`CC0-1.0`, `CC-BY-4.0`, `PUBLIC-DOMAIN`, `SELF-CREATED`) فقط سیاست آموزشی این پروژه است، نه تفسیر حقوقی. برای CC BY، کد وجود attribution و URL منبع را مطالبه می‌کند؛ این بررسی به‌تنهایی مجوز یا همهٔ حقوق لازم را اثبات نمی‌کند. شرایط وب‌سایت/مخزن، حقوق حریم خصوصی و publicity، دادهٔ شخصی، حقوق پایگاه داده و حوزهٔ قضایی را جداگانه بررسی کنید. دسترسی عمومی به صفحه به‌تنهایی مجوز آموزش نیست. در نمونهٔ پیش‌فرض هیچ متن شخص ثالثی وجود ندارد.

نرمال‌سازی به Unicode NFC و فشرده‌سازی فاصله‌ها محدود است؛ نیم‌فاصلهٔ فارسی حفظ می‌شود. ایمیل/شماره‌تلفن فقط با چند regex ساده flag می‌شوند؛ این ابزار آشکارساز جامع PII نیست و بازبینی انسانی همچنان لازم است. حذف تکرار فقط متن‌های **دقیقاً یکسان پس از همین نرمال‌سازی** را پیدا می‌کند؛ paraphrase، نسخهٔ نقل‌قول‌شده یا تکرار نزدیک را پیدا نمی‌کند. دادهٔ خام یا منبع را با hash جایگزین نکنید: hash یاری‌گر تمامیت است، نه مدرک مجوز.

## چرا split گروهی؟

دو بند از یک داستان، چند نسخه از یک صفحه، نویسندهٔ مشترک یا پیام‌های یک گفت‌وگو نباید تصادفی میان train و test پخش شوند، اگر قرار است تعمیم به منبعِ دیده‌نشده سنجیده شود. `group_id` باید این رابطه را با توجه به مسئله نمایندگی کند. ترتیب و نسبت گروه‌ها با seed تکرارپذیر است، اما برای corpus کوچک یا گروه‌های بسیار نامتوازن، شمار رکوردهای split ممکن است به‌طور محسوسی از نسبت درخواستی فاصله بگیرد.

## واژگان و پیوند به فصل بعد

Tokenizer این پروژه یک word-level baseline آموزشی است، نه BPE تولیدی؛ فصل ۳۳ الگوریتم‌های زیرواژه‌ای را جداگانه می‌آموزد. واژگان فقط از متن train ساخته می‌شود تا متن validation/test به پارامتر preprocessing راه پیدا نکند. واژهٔ ندیده به `<unk>` می‌رود؛ encode/decode فاصلهٔ اصلی را دقیق بازسازی نمی‌کند. فصل ۴۱ حلقهٔ آموزش و ارزیابی را روی دادهٔ آماده ادامه می‌دهد.

۲۰ آزمون واحد، schema و مجوز، تاریخ و ورودی خراب، دادهٔ حساسِ آشکار، Unicode، dedup، عدم نشت گروهی، تکرارپذیری، واژگان train-only، توکن ناشناخته، ذخیره/بازیابی tokenizer و ساخت artifactها را می‌سنجند. موفقیتشان فقط قراردادهای همین pipeline کوچک را تأیید می‌کند؛ نه کیفیت مدل، مجوز هر مجموعه‌داده، حذف همهٔ PII، عدم تکرار نزدیک یا تعمیم آماری را.
