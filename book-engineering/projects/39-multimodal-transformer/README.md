# پروژهٔ فصل ۳۹: اتصال رمزگذارهای تصویر، متن و صوت

این نمونهٔ CPU‌پسند سه رمزگذار کوچک را می‌سازد و خروجی هرکدام را به یک فضای تعبیهٔ مشترک می‌برد:

1. **تصویر:** `Conv2d` تصویر را به وصله‌ها (patches) تبدیل می‌کند؛ یک Transformer روی توالی وصله‌ها اجرا می‌شود.
2. **متن:** شناسه‌های توکن با ماسک padding از یک Transformer دوسویه عبور می‌کنند.
3. **صوت:** ویژگی‌های شبیه log-Mel در گروه‌های زمانی بسته‌بندی و با Transformer رمزگذاری می‌شوند.
4. **هم‌ترازی:** زیان InfoNCE متقارن، جفت‌های هم‌معنا را درون دسته به هم نزدیک می‌کند.
5. **ادغام:** متن به‌عنوان query با cross-attention جداگانه به توکن‌های تصویر و صوت دسترسی دارد.

پروژه برای آموزش شکل تنسورها، mask، مسیر گرادیان و تفاوت **embedding مشترک** با **cross-attention** است؛ کیفیت مدل یا هم‌ترازی واقعی را نمی‌آموزد.

## پیش‌نیاز و اجرا

- Python 3.11 یا جدیدتر
- PyTorch 2.6.x؛ CPU کافی است، CUDA لازم نیست.
- هیچ checkpoint، تصویر/صوت واقعی، dataset، شبکه یا کتابخانهٔ صوتی/بینایی اضافی لازم نیست.

از همین پوشه:

```bash
python -m unittest discover -v
python multimodal_alignment.py
```

خروجی نمونه:

```text
shared embeddings: (4, 16) per modality
fused text tokens: (4, 6, 32)
synthetic three-way InfoNCE: <عدد وابسته به وزن‌های تصادفی>
finite loss and gradients: True
```

عدد loss به نسخه، seed و اجرای PyTorch وابسته است؛ شکل‌های خروجی و آزمون‌ها معیار اصلی مثال‌اند.

## قرارداد ورودی و mask

- تصویر: `float [B,3,H,W]`، با H و W بخش‌پذیر بر اندازهٔ patch؛ پروژه تصویر را از مسیر فایل نمی‌خواند.
- متن: `torch.long [B,L]`؛ مقدار `0` نشانهٔ padding پیش‌فرض است. `text_padding_mask` بولی و با قرارداد **`True = padding / نادیده‌گرفتن`** است؛ هر ردیف باید دست‌کم یک توکن معتبر داشته باشد.
- صوت: ویژگی شبیه log-Mel با شکل `float [B,n_mels,T]`، نه waveform خام. `audio_lengths` تعداد فریم معتبر هر نمونه است؛ با stride چهار، طول معتبر به پایین گرد می‌شود و هر ردیف باید دست‌کم یک گروه کامل داشته باشد.
- embeddingها با L2-normalization به شکل `[B,embed_dim]` بازمی‌گردند.
- `symmetric_info_nce` فرض می‌کند جفت‌های مثبت روی قطر ماتریس similarity قرار دارند؛ نمونه‌های دیگر همان batch منفی فرض می‌شوند. برای batch یک نمونه، این تابع خطا می‌دهد چون منفی درون‌دسته‌ای وجود ندارد.
- `fused_text_tokens` حاصل پرس‌وجوی توکن‌های متن از توکن‌های تصویر و صوت است؛ decoder زبانی، پاسخ متنی، alignment زمانی صوت/تصویر، یا تولید صوت نیست.

## آزمون‌ها و مرزهای نتیجه

۱۵ آزمون واحد، شمار patch، شکل توالی‌ها، padding mask، طول معتبر صوت، نرمال‌بودن embeddingها، رفتار InfoNCE روی جفت مرتب/به‌هم‌ریخته، گرادیان هر سه encoder و هر دو شاخهٔ cross-attention، و رد ورودی‌های نامعتبر را کنترل می‌کنند. این تست‌ها صحت قراردادی همین پیاده‌سازی کوچک را نشان می‌دهند؛ benchmark سرعت، retrieval واقعی، کیفیت زبانی/دیداری/شنیداری یا توانایی zero-shot نیستند.

وزن‌ها تصادفی‌اند؛ دادهٔ آموزشی یا مثال جفت‌شدهٔ معنادار نداریم. بنابراین loss نمونه «بهبود مدل» محسوب نمی‌شود. تصویر از patch embedding یک‌بعدیِ ترتیبی استفاده می‌کند، نه هندسهٔ دوبعدی پیشرفته یا پردازش وضوح متغیر. صوت با گروه‌بندی خطیِ featureها ساده شده و STFT، waveform، VAD، codec، speaker diarization و streaming را پیاده‌سازی نمی‌کند. negatives ممکن است در دادهٔ واقعی false negative باشند؛ توابع آموزشی این موضوع را اصلاح نمی‌کنند. برای کار واقعی، داده و مجوز، preprocessing، مدل پایه، split، metric، زمان‌بندی و آزمون‌های عدالت/حریم خصوصی باید جداگانه مستند و ارزیابی شوند.
